# TASK-003：移动链接修复设计与只读预览

来源：用户要求开发 TASK-003；近期路线将其定义为“明确预览、选择、冲突与回退，规格确定后再实施”。本任务先交付可运行的规划边界，不实施真实回写。

## 场景与范围

用户准备将工作区内 Old.md 移到另一目录，希望知道其他笔记的指向和被移动笔记里的相对资源将受到什么影响。新增只读 CLI 与独立规划模块；现有应用移动入口继续原样工作，不自动迁移正文。

- 规划工作区中指向源笔记的 Markdown 链接，以及源笔记移动后需要重新定位的相对链接／图片。
- 使用语法树定位 URL 源码范围，只替换目标部分；保留标签、标题、尖括号、片段原文、BOM、CRLF 和所有无关字节。
- 支持内联链接、图片、引用式定义、中文／空格／百分号编码、平衡括号、Markdown 转义／实体与标题片段。
- Files.md 风格 `/路径.md` 普通笔记链接保持工作区根语义。图片和引用定义中的根路径有歧义，不自动规划；外部 URL、协议链接、片段自链、工作区外路径、查询参数和反斜杠路径不改，必要时列出诊断。
- 路径比较保留规范化拼写；Windows 大小写变体无法从纯文本确认真实身份时诊断并跳过，不能一律转小写合并文件。
- 不处理代码、YAML front matter、公式、HTML 块／包含内联 HTML 的整块、wiki／块引用、纯文本路径中的内容。目标不可明确解析时保持原样，不做全文替换。

## 本轮非目标

不新增桌面 UI，不改 moveDocument / DocumentStore / renderer，不增依赖或改版本，不实现“确认写入”或真正的撤回。TASK-002 正在编辑 package.json 与 UI 基准；本任务不改它们。

## 后续回写契约（设计，尚未实现）

1. 应用内规划由主进程建立，绑定工作区、移动身份、文件原始 SHA256 和完整扫描结果。renderer 只能提交计划 ID 与明确选择的编辑 ID，不能提交任意路径／新正文。预览默认不写；确认界面列出所选文件和 URL 差异。
2. 实际写入需要单独任务，在统一文件服务的队列中实施。提交前重新检查路径、磁盘摘要、编辑会话／恢复草稿与移动目标；原文或文件身份变动就拒绝旧计划，重新预览。未保存编辑或其他窗口拥有编辑权时不得覆盖。
3. 移动与多文件引用写入没有天然的跨文件原子性。后续应按文件保存原始字节备份和清单，逐文件版本检查后原子替换；准确报告成功、冲突、失败和未执行项，不宣称整个目录事务已原子完成。移动失败不应用引用编辑。
4. 撤回针对“本次引用修复”，不自动撤销文件移动。只有当前文件仍等于本次写入后的摘要且没有新的编辑／冲突时，才可由统一文件服务从备份恢复；否则保留备份并提示手动处理，不能用备份覆盖用户后续编辑。
5. 所有选择和冲突结论最终以确认时重新校验为准。CLI 的磁盘预览没有应用内编辑会话信息；即使 complete=true，也不是安全写入授权。没有调用者提供的回写能力，本任务代码不能执行上述任何持久化动作。
