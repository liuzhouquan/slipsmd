# TASK-001：多 agent 协作与开发路径

任务：[Issue #1](https://github.com/liuzhouquan/slipsmd/issues/1)。状态与实际交付以对应 PR 为准。来源：用户要求新特性默认在新分支／worktree 并行开发，交叉审核 PR 后合并，并保留统一进度与路线文档。

## 范围

建立仓库可携带的协作协议、轻量 SDD 模板、单一进度入口、PR 模板和可审计的主线保护配置。保留现有产品和历史文档，不将早期功能补写成已执行的 SDD。不改产品行为、版本或依赖，不引入自动 agent 调度服务。

## 验收条件

| ID   | 结果与证据                                                                                                     |
| ---- | -------------------------------------------------------------------------------------------------------------- |
| AC-1 | 新 agent 可从 AGENTS.md 找到基线、路线、规格、计划、进度与验证入口，架构中的过时实现说明得到修正               |
| AC-2 | 明确一任务一分支一 worktree、单写入者、分配与交接、共享接口和集成顺序；使用现有 projects 布局                  |
| AC-3 | PR 模板与流程要求另一 agent 审核实际 HEAD，修改后复核；明确同账号报告不等于 GitHub 正式 approve                |
| AC-4 | main 的保护要求 PR、两平台 Actions、线性历史、禁止强推／删除且适用管理员；不设置无法由同账号完成的正式自我批准 |
| AC-5 | 本任务自身通过 worktree → PR → 独立审核 → CI → 合并，并留下链接与检查证据；保护配置应用后读回核对              |

## 非目标与约束

不声称任意独立会话自动共享上下文或能自动联系。不把文档当成原子任务锁、消息总线或服务端验证的双人审批。未来增加独立 GitHub 评审账号后再明确调整正式批准数。
