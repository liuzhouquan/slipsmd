# 开发计划

已按用户决定采用 CodeMirror 6，实现首版 alpha。实际范围、运行方式和限制以 README 为准，验证记录见 validation.md。

阶段 1–3 的基础文件、多窗口、链接、Chat、图片和主题已实现；原先阶段 0 的 Muya 实验已被 CodeMirror 6 路线取代。Windows IME 人工验证和大库性能尚待后续。逐文档阅读位置已在 alpha.5 实现，文件重命名／工作区内移动已在 alpha.6 实现。以下保留初期阶段划分用于追踪，不表示所有项目已完成。

## 阶段 0：编辑器与桌面验证

目标：证明推荐组合能够支持现有笔记和 Windows 日常编辑，再锁技术栈。

1. 新建最小 Electron + Vue + TS 宿主，接入锁定版本的 CodeMirror 6；先整理其语言扩展、预览组件与 CSS，不引用 MarkText 整个 UI。
2. 打开实际 Markdown 样本，覆盖列表、表格、代码、数学、Mermaid、YAML、相对图片、中文与编码；比较打开前后和实际编辑后的 diff。
3. 在 Windows 验证微软拼音组合输入、选区、跨块删除、粘贴、撤销重做与切换文件前 flush；不能仅用 DOM 单元测试代替 IME 手工验证。
4. 打开 3–5 个真实系统窗口，验证文件树与 Ctrl+点击路由、独立滚动与主题；同文件重复打开策略先用可见提示验证。
5. PicGo GUI 做一次临时图片上传闭环，包含失败、撤销和切换文件后的返回处理。
6. 记录环境、冷启动、1/3/5 窗口总内存、发行体积及大文档输入感受。数值目前不预设成已经实现的指标。

通过条件：关键语法不丢内容；没有不编辑却自动改写磁盘文件；中文输入、撤销与多窗口基本可靠。记录可接受的格式归一化差异，无法保留的语法明确处理。

如果 CodeMirror 6 预览出现限制：先判定是配置、适配还是内核限制；比较 HyperMD 保留现有体验、CodeMirror 6 强调源码保真、Milkdown 富编辑三个方向。若 Electron 资源占用无法接受，在相同文档和操作场景比较 Tauri；不同时做四套完整产品。

## 阶段 1：文件与多窗口基础

- WindowService、DocumentService 和工作区身份，明确同文件编辑权。
- 文件树、单文件打开、文件夹打开、新建、保存、最近文件和窗口会话。
- 编辑器、Chat 与文件操作统一保存队列，识别外部修改，保留崩溃草稿。
- Windows 安装／便携产物选择、文件关联、新窗口命令；具体发行渠道待决定。
- light / dark / system 三态主题和跨窗口持久化。

验收：A、B 两个文件可同时编辑；关闭其中一窗不影响另一窗；记事本或第三方同步修改已打开文件时不会静默覆盖双方内容。文件夹嵌套、中文、空格、重名文件和大目录有明确表现。

## 阶段 2：链接与上下文阅读

- 当前工作区链接补全、路径解析、反链索引与反链列表。
- 内部链接在右侧打开、连续导航、返回前进、各视图位置恢复。
- Ctrl+点击内部文件／链接打开新窗口；普通选择文字不误跳转。
- 兼容 Files.md 根路径链接，支持原生相对路径；删除、改名、断链均能反馈。

验收：A 链 B 后 B 显示来自 A 的反链且正文不变；A 的链接在右侧打开 B，B 继续进入 C 后能返回；代码里的假链接不入索引；工作区外快捷方式不自动变成跨库索引。

## 阶段 3：首版产品闭环

- Chat 快记：输入即可持久化，无需标题和分类；再补整理到现有／新文件的动作。
- Chat 与其原文编辑器同时打开时，快记不被旧正文覆盖；整理失败可恢复。
- PicGo 粘贴图片自动上传与设置、失败重试、本地保存选项。
- 选定稳定发行的 Markdown 能力，补齐日常查找、快捷键和必要帮助。

验收：随手记录 → 阅读相关笔记 → 新窗口写作 → 插图 → 整理的完整流程可用；上传期间切换文件、撤销、退出重启均不丢图片或写错文档。完成这些后才称为桌面 MVP。

## alpha.4：全局快捷方式

已实现 F09：固定当前 Markdown 文件／工作区、系统选择外部文件／目录、去重、跨窗口同步、重启保留、失效路径提示、取消固定及 Ctrl+点击独立窗口。文件快捷方式保留当前工作区，目录快捷方式切换工作区；所有正文写入仍经过 DocumentStore，切换前先保存。外部单文件不加入当前库索引。

## alpha.5：逐文档阅读位置

主区与右侧分别保留笔记的正文位置、选区和源码／预览模式。右侧返回／前进、关闭后重开与主区切换均可恢复；正文宽度变化时按内容锚点定位，初次布局完成前的高度变化会重新校正，主动滚动或输入立即接管。新笔记从顶部开始，磁盘文件变短时限制选区范围。缓存仅保存在当前窗口内，每区最近 100 份，不保存正文，不在窗口之间同步，不承诺退出后恢复。

## alpha.6：文件重命名与移动

主区 F2 和两侧编辑器铅笔入口打开可键盘操作的模态表单。工作区内使用相对路径移动到已有目录；外部单文件只能在同目录改名。提交前锁定编辑并保存，文件服务同时锁定两条路径，校验版本后通过独占硬链接和移除旧名称完成移动，不覆盖已有目标。已打开视图、标题、右侧历史、阅读位置和固定入口同步新路径；正文的链接／相对图片路径不会自动重写。收集箱 Chat.md 保留固定路径，跨文件系统与不支持硬链接的位置拒绝操作。

下一轮候选：长文与大库性能、移动后的链接修复方案、文件夹操作。窗口内 tabs、任意多列、图谱、跨库双链、Telegram 和远程 Web 入口继续留在后续范围；真实 Windows IME 与 PicGo 的人工体验仍未代测。

## 阶段 4：次级功能

由实际使用反馈决定顺序：全局 sidebar 文件／目录快捷方式（已实现）、窗口内标签页、多列链接堆叠、图谱、可选 Telegram 远程收集。多工作区双链单独设计，不能因为实现收藏就自动纳入。

## 阶段 5：浏览器远程入口

提取或复用共享 UI 与业务，添加 RemoteWorkspaceAdapter 和服务端存储。单用户自托管登录先于多租户产品；远程保存有版本冲突处理。上传器与本机 PicGo 分开处理，不自动追加整库同步和多人实时协作需求。

## 验证与依赖门槛

实现时围绕真实风险建立验证：路径解析和反链、版本冲突、同文件并发写、Chat 整理恢复、图片异步响应、中文输入和窗口路由。已有检查通过后不无意义重复运行。只写与业务风险有关的检查，不为简单文档和可逆配置堆测试。

当前已安装依赖并提供 package-lock.json。后续升级 Node/Electron、Vue、Vite、TypeScript 与 CodeMirror 时更新锁文件并运行相关检查。引用代码前记录来源许可，不让本地 reference 路径成为发行构建依赖。
