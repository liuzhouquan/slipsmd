# 需求与讨论笔记

日期：2026-11-27。本文区分用户已经表达的需求与实现建议，后续讨论继续增补。

## 项目动机

用户喜欢 Files.md 的产品逻辑，日常最常用 Typora。希望建立一个开源项目，融合前者的工作区、关联笔记和低负担记录流程，以及后者的编辑体验与桌面窗口操作，而非复刻任何一个产品的全部功能。

用户补充：首版 **Windows 优先**。已确认 Electron + TypeScript + Vue 3 + CodeMirror 6，将来有提供浏览器在线编辑服务器 Markdown 文件的可能。

## 品牌要求

首期只使用英文名称，不设置中文别名。此要求只针对品牌标识，不改变中文界面与中文输入需求。原项目名已发现同名产品，现由用户确认改为 **slips.md**；目录、应用标识、远程仓库与发布包同步调整。

## “分页”的澄清

此前将“分页”理解为纸张排版，这是误读。本项目实际讨论三个不同能力：

1. 多独立系统窗口：核心。可以简单地打开几个窗口，同时查看或编辑不同文件，不必手工操作浏览器窗口。
2. 窗口内标签页：次级。类似浏览器、Notion 的多个页面 tab，可后续加入。
3. 右侧关联内容面板：核心。保留 Files.md 点击链接后在右侧打开另一份内容的体验。

纸张分页引擎不属于当前需求。PDF、打印也不因这次讨论自动成为首版任务。

## 产品交互草案（建议，待原型细化）

- 文件树单击文件：在当前主编辑区打开。
- 文件树或正文内部链接 Ctrl+点击：在独立窗口打开；macOS 后续映射为 Cmd+点击。
- 正文内部链接的普通导航动作：在右侧关联面板打开；具体使用单击或可见链接按钮，要避免干扰放置光标和选择文字。
- 右侧面板可以继续打开关联内容，并保留返回、前进及各文档滚动位置；第一版先做一个右侧面板和导航历史，任意多列堆叠是后续增强。
- 提供“在当前区域／右侧／独立窗口打开”的菜单，使动作不只依赖快捷键。
- 不同文件可以在不同窗口或面板同时编辑；同一个文件的重复编辑策略需要统一定义，不能静默互相覆盖。
- 打开单文件不自动递归扫描其整个父目录；选择打开文件夹后才成为有索引的工作区。
- 外部快捷方式属于应用级收藏，不等于把所有收藏目录合并为同一个知识库。
- Chat 是想法收集箱，不自动引入 AI 聊天。建议每个工作区有自己的 Chat.md，单文件模式可打开上次使用的收集箱；具体归属仍待讨论。

## Markdown 能力目标（建议清单）

普通段落、标题、强调、引用、链接、图片、代码块及高亮、列表、任务列表、表格、撤销重做、查找替换是日常编辑基础。公式、Mermaid、YAML front matter 应进入编辑器原型，确认能承接用户现有笔记；“Files.md 支持得完善”不代表未经验证就能完整兼容所有 Typora 扩展。

## 后续讨论项

- 编辑效果：是否接受默认隐藏 Markdown 标记、光标进入时显露；源码模式是否首版必需。
- 同文件重复打开：推荐默认聚焦已有可编辑窗口；显式重复打开时展示只读镜像，后续可转移编辑权。
- 链接语法：标准 Markdown 路径链接为首选；是否同时写入 [[wikilink]] 尚未确定。
- Chat 归属、归档与整理动作：先保留收集核心，再用原型确认移动、复制、日记和任务流程。
- 全局还是每工作区设置主题、是否允许窗口独立设置：推荐首版统一应用主题。
- 开源许可证：用户已确认 MIT，GitHub 仓库公开。
