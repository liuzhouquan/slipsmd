# 移动链接修复预览（TASK-003）

这是从源码运行的只读开发工具，先验证“应当改哪些 URL”。不执行文件移动、不回写笔记，也不接管应用里的移动对话框。实际确认写入与撤回属于后续实现，契约见 [任务规格](tasks/TASK-003/spec.md)。

## 运行

需要 Node.js 24，并在本工作树完成 `npm ci`。从仓库运行（也可使用脚本绝对路径，从其他目录调用）：

```sh
node scripts/preview-link-repair.mjs --help
node scripts/preview-link-repair.mjs \
  --root /path/to/notes \
  --source Notes/Old.md \
  --target Archive/New.md
```

参数也支持 `--name=value`；例如源文件名以 `--` 开头时用 `--source=--Old.md`。`--root` 是工作区目录；source / target 均为相对工作区路径。源必须尚未移动，目标及其父目录按现有移动规则预检：父目录需存在、目标不得存在，省略 Markdown 扩展名会补 `.md`。工作区根部 Chat.md 保留为收集箱。这里只预检路径，不保证文件系统支持未来真正的移动。

临时构建仅放系统临时目录，结束后清理；扫描器没有写入接口。若工作区覆盖整个系统临时目录，CLI 拒绝运行，避免自身构建写进被声明为只读的范围。

## 报告和选择

JSON 报告含 `readOnly: true`、移动前后路径、`complete`、`planId`、`files`、`diagnostics` 和统计。每个受影响文件包括：

- `pathBefore` / `pathAfter`：源笔记在未来目标位置应用其资源重定位，其他笔记保持原路径。
- `beforeRevision`：原始 UTF-8 字节的 SHA256；`beforeIdentity`：本次扫描的文件设备／身份信息。
- `edits`：编辑 ID、URL 目标的 `before` / `after`、行号、类型和 `from` / `to`。范围为 **JavaScript UTF-16 偏移**，不是 UTF-8 字节下标。

`summary.scannedBytes` 是已成功校验的正文总字节数；`proposedEdits` 为原计划建议数，`selectedEdits` 为本次所选数量。默认列出全部建议；选择不写文件，只生成过滤后的预览：

```sh
node scripts/preview-link-repair.mjs \
  --root /path/to/notes --source Notes/Old.md --target Archive/New.md \
  --plan-id 'COPY_THE_64_CHARACTER_PLAN_ID_FROM_THE_REPORT' \
  --select e000001,e000003
```

将示例中的计划 ID 和编辑 ID 换成实际报告值。选择前会重新扫描；任何笔记内容／身份／元数据或目录清单的变化都可能使计划过期。未知或重复 ID 拒绝；`--select ''` 可预览不选择任何项，仍需匹配的完整计划。ID 不能跨计划复用。

计划摘要绑定本次扫描，不是写入授权。工具没有应用内未保存编辑／会话所有权信息，不能据此绕过统一文件服务直接写盘。

## 支持和边界

规划 Markdown 内联链接、图片、引用式定义的 URL；只更改精确目标范围。更新其他笔记指向源文件的路径，也重新定位源笔记移动后的相对资源路径。标签、标题、尖括号、原始 fragment、BOM / CRLF 和无关内容保留；新路径按 URI 路径段编码。

外部协议和 fragment 自链保持不变。代码、front matter、公式、HTML 块／带内联 HTML 的整块、wiki／块引用、纯文本路径不作为修复来源。带查询参数、编码无效、控制字符／反斜杠、越界目标及图片／引用定义的 `/根路径` 会保持原样并诊断；普通 `/笔记.md` 使用现有 Files.md 工作区根语义。

预览保持资源原先解析出的工作区内字面目标，不检查图片／其他资源是否实际存在；无关媒体不会被读取。非标准 Markdown 和无法明确识别的语法不承诺完整覆盖。

元数据复核不是全库原子快照，末次检查后仍可能发生外部变化，因此任何实际回写都必须再次检查。扫描与文件树一致，排除隐藏目录、忽略目录与符号链接；可见普通 Markdown 的目录清单、读取前后文件身份及扫描结束时元数据都会核对。上限为 10,000 篇、24 层、单篇 20 MiB、累计预留读取预算 64 MiB、10,000 项建议，单篇 URL／排除区段合计 20,000 项、诊断 1,000 项；失败、超限或变化产生不完整报告，不能选出可执行方案。

`complete=true` 只表示本轮受支持的扫描覆盖完成，仍需检查 warnings；不表示全部语法已覆盖、资源都存在、没有其他窗口编辑或可以安全写入。退出码：0 为完整报告，1 为参数／预检／选择错误，2 为不完整扫描。报告只打印到 stdout，不自动保存。

## 后续回写与撤回

确认界面应逐项展示并让用户明确选择；主进程持有可信计划，统一文件服务逐文件复核原文摘要、身份、会话和恢复草稿。移动失败不应用引用编辑；每文件保留原始字节备份与清单并准确报告部分成功／冲突，不能宣称跨文件原子事务。撤回只恢复仍等于本次写入结果、没有后续编辑的文件，不自动撤销文件移动；否则保留备份供手动恢复。这些持久化能力本轮尚未实现。
