# 首版验证记录

版本：0.1.0-alpha.9。日期：2026-11-27 至 2026-11-28。以下记录区分本地检查、CI 和人工验收，不把某个平台的结果外推到其他平台。

## 本地环境

开发与桌面验证在 Linux / WSLg 中进行，Node.js 24、Electron 45、Vue 3、CodeMirror 6。Electron 下载包与 npm 包内附的官方 SHA256 清单核对后使用。测试启动时的 --no-sandbox 仅用于测试环境；正常应用代码保持 renderer sandbox 和 contextIsolation 开启，nodeIntegration 关闭。

## 自动检查

- `npm run typecheck`：Vue、renderer、preload 和 main 的 TypeScript 检查。
- `npm test`：真实临时文件上的 BOM/CRLF 保留、外部冲突、草稿恢复、重复编辑所有权、串行写入、Chat 追加冲突、外部删除后的恢复保护，以及链接解析。
- `npm run build`：三个入口构建，生成依赖许可声明。
- `npm run test:desktop`：启动真实 Electron 窗口，通过 Playwright 操作 CodeMirror、文件树、独立窗口、收集箱、图片、设置和冲突界面；生成临时截图，不接触用户文件。
- `npm audit`：检查锁文件依赖。打包工具的 minimatch 使用 11.0.1 修复版本覆盖，需随打包流程一起验证。

桌面测试中的 PicGo 是本机模拟 HTTP 服务：验证请求里传入的是实际临时图片路径，以及返回 URL 被正确写入 Markdown。这不等于已在用户的 PicGo 与图床上测试成功。

alpha.4 已通过 26 项文件／链接、Chat、迁移与快捷方式路径测试。真实桌面流程覆盖固定当前文件／目录、去重、未授权路径拒绝、外部选择结果、跨窗口同步与同时固定不同目标、外部文件图片、工作区切换前保存、失效路径处理、取消固定不删除、重启保留。源码与 Linux 打包版本的完整桌面流程均已通过，界面检查覆盖亮色、暗色和 760×540 视口；Windows 与 Ubuntu 已通过 [CI 46013495945](https://github.com/liuzhouquan/slipsmd/actions/runs/46013495945)，验证代码提交为 `5768efe4ab368ad663102d53802b8c9c48c3b4ca`；两个平台均通过 26 项测试、源码桌面、打包和打包后完整桌面流程。

快捷方式流程只替换原生文件选择器的返回值；主进程路径校验、授权、设置落盘与应用重启真实执行。系统选择器本身的人工操作尚需体验。

## alpha.9 增量工作区索引

本地通过格式检查、70 项单元测试、类型检查、生产构建与七组完整源码桌面流程。早期全量检查出现过一次阅读位置偏差，单独复核及最终代码的全量检查均通过；本轮没有修改阅读位置实现，相关流程继续由两平台打包回归核验。

新增 10 项针对性测试覆盖热缓存、恢复 mtime 的外部同尺寸修改、编辑文本覆盖及关闭后磁盘回退、并发查询合并／最多 8 个文件句柄、扫描中失效与后加入查询的一致性、移动／删除清除旧来源、无效 UTF-8／二进制／超大文件、目录链接越界、扫描失败后重试和纯内存扫描让出事件循环。

新增第七组真实 Electron 流程检查两个窗口查询同一工作区、未保存暂存文本的反链、保存后 BOM／CRLF、立即查询外部改写／删除、隐藏目录排除，以及一个窗口切换工作区后同名笔记的索引隔离。

基准命令 `npm run benchmark:index -- 1000` 使用临时合成笔记，并生成 `.test-results/index-benchmark.json`。本地 Node 24 / Linux 的首次测量为：冷建索引 974.29 ms，热查询 115.00 ms，单文件外部修改 117.36 ms，四个重叠查询 115.38 ms；对应正文读取／解析数为 1000、0、1、0。不缓存且读取并发同为 8 的单次对照为 422.57 ms。该测量表明重复工作减少，同时冷建索引有额外校验成本；不是整应用启动、输入延迟或真实任意工作区的性能结论。两平台 CI、完整桌面与打包结果通过后补录。
